### How the existing `ai.py` import guard works

`backend/tests/test_ai.py:42-53` parses `ai.py` source with `ast`, collects every `import X` name and every
`from X import ...` module (relative ones written as `.module`), then asserts (1) none is in a forbidden set
(`subprocess, os, shutil, socket, .safety, .orchestrator, .faults, .docker_cli, .guardrails, .api, .evidence,
.sdv_adapter`) and (2) the set is a subset of an allowlist (`__future__, json, dataclasses, pathlib, urllib.parse,
httpx`). It is static and checks **direct** imports only; it does not execute the module or follow transitive imports.
The new guards will use the same AST technique.
